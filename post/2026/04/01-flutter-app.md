# Flutter App 开发初体验

**Claude Code**

Claude Code 出来已经一年多了，作为一个干啥都慢半拍的程序员，决定上手玩一玩。

考虑到 A 社是个中国黑，它本家的模型就不指望了，好在国产大模型追的也猛，就开了个 MiniMax 的 Token Plan，毕竟 M2.7 刚出。

安装没啥大问题，官网好像悄咪咪把 npm 安装移除了，看来愚人节前夜对他们伤害很大。

装好后跟着 MiniMax 的文档 https://platform.minimaxi.com/docs/token-plan/claude-code 配置即可，不用 /login 那个是登录他们自家产品用的。

装完就发现自带的 web_search 和 Fetch 用不了，即便开着代理也有部分网站无法访问，坑爹。

恰巧 MiniMax 一个网络搜索 MCP，这可太及时了。但它的一键安装命令在我的 Windows Terminal 下无法执行，会报 -y 什么什么的，只能手动配置。另外就是配置完不一定能连上，我是开代理后连上的，但连上后关了代理也正常，不知道啥情况。

**Flutter 安装**

安装基本没啥大问题，按照官方文档来就是了，真有问题也是网络问题。网络问题终极杀招就是代理开 Tun Mode 也就是所有流量都走代理，如果这招也搞不定，那只有烧香祈福了。

需要注意的时要验证下 Tun Mode 是否开成功，比如没开的时候用浏览器打开 google.com 必须是打不开的，开了之后能打开 google.com 那就说明是真打开了。

有些代理软件，比如我用的黑色猫猫头，每次打开 Tun Mode，要点一下扳手，安装一个服务，才能真正打开，被它套路过一次。

装完最好装一下 Android Studio，主要是为了装 SDK，Android Studio 是可以设置代理的，第一次装也要下载不少东西。

再然后准备设备，电脑够猛的可以上模拟器，我电脑太烂，出风口可以把鸡蛋吹的比刚出锅还要烫。

翻出来一台远古的 MI 8 SE 来当真机，连上数据线后，执行命令

```
adb tcpip 5555
adb connect 192.168.31.115:5555
```

可以无线调试，这时候就可以拔掉数据线，用命令

```
adb devices
```

能看到连接的设备。无线连接还有个好处，没啥权限问题。我用 USB 调试时，安装 apk 包，各种失败，这那的问题。无线连接屁事没有。

**开发**

接下来是决定做什么 App，看到老爹最近沉迷短剧，那就做个短剧 app 吧，下载红果免费短剧 app，截了 5 张图，然后输入

```
@Screenshot\\ 这个文件夹保存红果免费短剧 app 的截图，现在需要你根据截图，开发一个仿红果免费短剧 app
```

这一步非常惊艳，确实把截图七八成的样子还原出来了，

接着去抖音下载几集短剧当测试数据。

视频播放也很顺利，很快就可以播放了

接着开发上滑，然后噩梦开始了。

首先遇到的是怎么滑都没反应，为了确定问题又是打印索引，又是显示滑动距离，都没用。

反复在修改 --> 安装 --> 测试循环。

终于在某一次它说可能是手势冲突了，说什么 SurfaceView 这了那了，也不是很懂，改就完了，改完后确实有反应，能够显示滑动距离。

又经过一轮轮对话，它终于滑得动了。尽管滑起来异常抽象，但至少能动了。

随之就发现一个问题，我放了 3 集测试数据，但是它只会在 1,2 集切换，谁说 AI 没想法，我看它有想法的很。

又是漫长的配合他调试，修改、安装、测试。觉得这么做不合适，

先是让它自己写了单元测试，效果不佳，单元测试都能通过，问题依然存在。

看来必须得上集成测试，让它调研

![](e2e-3.png)

他管这种叫 E2E 测试，又学到一个新名词

根据它的报告，选择 Patrol，即是本家 integration_test 的增强，底层用的是原生，听起来就感觉很靠谱。不靠谱也无所谓，反正都是 AI 写

让 AI 编写首页滑动的测试用例，它写了三个


| #  │                          用例名称                          │               测试内容               │
| --|--|--|
| 1  | home page swipe up changes to next episode|向上滑动从第1集切换到第2集|
| 2  | home page swipe down from episode 2 goes back to episode 1 | 向下滑动从第2集返回第1集|
| 3  | home page swipe up twice reaches last episode | 连续上滑两次到达第3集 |

然后让它再次验证，这一次它开始自循环了，它自己改完，然后运行用例验证，然后失败

截止目前，这个任务至今已经运行四个小时了，问题依然没有解决，我也不知道它能不能解决。

不管最终能否解决，它这种自循环模式很恐怖。西蒙大佬曾经有一篇文章介绍从零开始写浏览器引擎 FastRender。是因为浏览器引擎有大量测试用例可以自循环。

前阵子 Cloudflare 花一周重写了 Nextjs，大概也是利用了它无比丰富的测试用例。没想到软件开发最重要的东西是一致被开发嫌弃的测试。

这次玩下来，虽然嘛也没干成，但那种感受更深了，我这用的还不是 Opus 4.6。
